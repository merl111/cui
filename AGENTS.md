# Working with CUI

CUI is a C99 native desktop GUI framework with a public C ABI and Rust, Python,
Go and Zig bindings. Linux uses GTK 4, macOS uses AppKit, and Windows uses WinUI 3
with Win32 window integration. It is an early prototype; API/ABI stability and
complete cross-platform behavior are not promised.

## Start here

- Read [README.md](README.md) for platform setup and current verification status.
- Use [the CUI skill](skills/cui/SKILL.md) for capability selection, app integration,
  lifecycle rules and runnable examples. Its reference paths are relative to this repository.
- Treat `include/cui*.h` as the API contract. Confirm binding names in `bindings/`
  and working examples before using them; plans describe intent, not shipped behavior.
- The toolkit provides controls, layouts, desktop integration, canvas drawing,
  icons and reusable chat UI. Applications provide networking, persistence,
  authentication, Matrix services and call media.

## Code and documentation map

- `src/cui.c`, `src/cui_layout*.c`: ownership, shared widgets and layout.
- `src/cui_gtk*`, `src/cui_macos*`, `src/cui_winui*`, `src/cui_win32.c`:
  platform backends. Windows build configuration is in `cmake/CuiWinUI.cmake`.
- `src/cui_chat*`, `src/cui_draw*`, `src/cui_raster.c`: shared chat and drawing.
  Keep rendering and reusable component behavior in C; bindings marshal data/events.
- `bindings/{rust,python,go,zig}`: language APIs; `examples/` and binding examples
  demonstrate integration. `tests/` contains layout, native and binding checks.
- `docs/guides/`, `docs/components.md`, `docs/desktop.md`: usage and limits.
  `docs/site/README.md` explains the generated website; author sources, not `build/docs`.

## Contracts to preserve

- One app, all CUI calls on the main thread. Quit in callbacks; destroy the app
  only after its event loop returns. Closing a window hides it; handles remain
  valid until app destruction. Individual widget destruction is not supported.
- Strings are UTF-8, geometry uses logical units, and native minimum sizes matter.
  Prefer semantic roles and platform fonts; check high DPI and enlarged text.
- Programmatic value setters generally suppress callbacks; explicit actions can
  emit events. Follow each header's ownership, copying and event contract.
- Keep callback data alive. Icons and drawing surfaces have independent reference
  counts; app ownership of widgets does not release the caller's asset references.
- Public ABI changes require corresponding bindings and consumers to be rebuilt.
  Update generated Rust declarations with `tools/generate_rust_bindings.py`.

## Build and validate

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCUI_BUILD_TESTS=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Linux requires `pkg-config`, GTK 4.6+ with X11, and Xext development files.
GUI tests need Xvfb; check `ctest --test-dir build -N` so absent GUI tests are not
mistaken for passing coverage. Use an isolated build directory if existing build
settings serve other work. Windows uses the README's Visual Studio commands;
native Windows/macOS execution is necessary to claim verification there.

Run checks appropriate to the change: public API/bindings use
`python3 tools/check_bindings.py`, `python3 tools/generate_rust_bindings.py --check`
and `python3 tools/check_rust_abi.py`. Enable `CUI_BUILD_BINDING_TESTS=ON` for
installed language toolchains on Linux. For documentation/site changes, follow
`docs/site/README.md`, then run `python3 tools/build_docs.py` and
`python3 tools/check_docs.py`. Refresh affected native captures with their
provenance when sources change. For memory investigations, see
`docs/guides/memory-safety.md` and `python3 tools/check_memory.py all`.
